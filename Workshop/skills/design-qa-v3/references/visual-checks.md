# Visual comparison checks

Use after the reference and app have been matched. Select checks relevant to the actual screen rather than assuming every category applies.

| Area | Compare | Evidence |
| --- | --- | --- |
| Section | Heading, alignment, padding, gaps, background boundary | Matching section captures with neighboring context |
| Card | Corner shape, border, shadow, image crop, image/body boundary | Matching card captures at comparable scale |
| Text | Hierarchy, relative size, weight, wrapping, spacing, visible information | Readable captures showing the same content |
| Supporting elements | Icons, badges, prices, timestamps, overlaps, tilt | Close-up plus enough context to locate it |
| Repeated components | Consistency across visible instances | Locations and instances actually checked |
| Page coverage | Below-fold sections and horizontally scrolled content | Coverage log and captures of inspected regions |

Match states before claiming differences. If copy differs, distinguish a content change from a layout effect caused by the content. Avoid prescribing exact pixels or colors from an uncalibrated image. Rendering, font loading, scaling, or compression can affect a comparison; note these when they materially limit the finding.

For every planned check use one of: matched, different, not applicable, unverified. An unchecked region is not a confirmed match.
