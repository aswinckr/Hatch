# Interaction checks

Read only when interaction testing is requested and a live app is available.

- Use ordinary clicks, scrolling, typing, and keyboard navigation. Stay within the agreed task; do not submit orders, payments, or messages.
- Write the starting state, exact action, observed response, and reproduction steps.
- Use a supplied interaction requirement or prototype as the expected behavior. If none exists, distinguish a usability concern from a proven specification mismatch.
- Capture relevant before and after states. Restore the agreed initial state before comparing another version.
- A visible icon does not prove a working action. A screenshot alone does not establish keyboard access, hit area, focus behavior, or a contrast ratio.
- If testing is unavailable, mark the behavior unverified. Do not infer invisible implementation details.
