# Three reference versions

These are complete teaching examples, not measured model-run results. Create your own versions during the workshop, then compare with these when the teacher releases each checkpoint.

| Version | What changes |
| --- | --- |
| [Version 1](design-qa-v1/SKILL.md) | A short task and shared evidence boundary |
| [Version 2](design-qa-v2/SKILL.md) | An explicit visual procedure, checklist, and evidence-backed reporting |
| [Version 3](design-qa-v3/SKILL.md) | A compact workflow with conditional references and reporting decisions |

Use only one version in each fresh audit task. Keep other versions, this repository, prior reports, and teacher materials out of that task's accessible inputs. In an authoring task, the agent may edit your selected skill. In an audit task, it should use the frozen version.

For Codex, local repository skills can be placed under `.agents/skills`. Use a separate participant authoring workspace rather than the full Hatch checkout. Select or mention the skill explicitly during timed comparisons. These supplied skills leave automatic selection at its default; the invocation exercise explains how to choose otherwise. [Official skill documentation](https://learn.chatgpt.com/docs/build-skills).

Other coding agents may use different installation folders or invocation controls. Use the host's documented skill mechanism, or attach the selected skill and its resources directly for a practice run and label that method on your worksheet.

The skills intentionally contain no screen-specific answer list or required finding count. The visual comparison method can apply to another interface with a supplied reference.
